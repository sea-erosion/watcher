# カクヨムリーダー サイト（Vercelデプロイ用）

`kakuyomu_scraper.ipynb` で作成した zip（HTML版 / txt版）をアップロードすると、
ブラウザ上でそのまま読める Next.js サイトです。

- アップロードした zip は **サーバーには送信されません**。ブラウザ内で JSZip により展開し、
  IndexedDB にのみ保存されます（完全にクライアントサイドで完結）。
- そのためバックエンドやデータベースの用意は不要で、Vercel に静的サイトとしてそのままデプロイできます。
- 読書画面には notebook のHTML版と同じ「テーマ切替（ライト／セピア／ダーク）」
  「文字サイズ調整」「表示幅調整」のツールバーが付いています。
- **完全なPWAとして動作します**。一度オンラインでサイトを開けば、以降はどの話を開いても
  オフラインで読めます（詳細は下記）。

## オフライン対応について(完全PWA化)

このサイトは `next.config.mjs` で `output: "export"` を指定し、サーバー機能を一切使わない
**完全な静的サイト**としてビルドされます（Vercelのサーバーレス関数にも依存しません）。

以前は「話ごとにページが分かれていた（`/read/1`, `/read/2`, ...）」ため、オフラインでは
一度も開いたことがない話が読めないという制約がありましたが、現在は本文ページを
`/read?num=5` のように**1つの静的ページ＋クエリパラメータ**で表示する方式に変更しました。
話を表示する処理は全てブラウザ内のJSが行うため、ページ自体は常に1種類しかなく、
**一度 `/` → `/work` → `/read` の3ページをオンラインで開いておけば、その後はアップロードした
全ての話をオフラインで開けます**。

- Service Workerがサイト本体（HTML/JS/CSS/アイコン）をキャッシュ
- 小説データ自体（IndexedDBの中身）はオフライン/オンラインに関係なく常に保持されます
- スマホ/PCのブラウザで「ホーム画面に追加」「アプリとしてインストール」することで、
  ネイティブアプリのように起動することもできます（インストール後は完全オフラインで動作）
- 新しいzipのアップロード自体はもちろんオフラインでも可能です（zip展開はブラウザ内のJSのみで完結するため）

## ローカルで試す

開発中（ホットリロードあり）:

```bash
npm install
npm run dev
```

<http://localhost:3000> を開いてください。

本番ビルド＋PWA(Service Worker)の動作込みで確認したい場合は、ビルド後に静的ファイルを配信します
（`output: "export"` を使っているため `next start` は使えません）:

```bash
npm run build
npm run start   # out/ フォルダを静的配信します
```

## Vercel へのデプロイ

### 方法A: GitHub経由

1. このフォルダの中身をGitHubリポジトリにpushする
2. <https://vercel.com> にログインし「Add New Project」→ 該当リポジトリを選択
3. Framework Presetは自動的に「Next.js」が検出されます。ビルド設定はデフォルトのままでOKです
4. 「Deploy」をクリックすると数分でURLが発行されます

### 方法B: Vercel CLI

```bash
npm i -g vercel
vercel
```

指示に従ってログイン・プロジェクト作成を行うとデプロイされます。

## 使い方

1. notebookのセクション9〜11（HTML版）、またはセクション4・8（txt版）を実行してzipをダウンロードする
2. このサイトのトップページでzipをアップロード（ドラッグ＆ドロップ、またはクリックして選択）
3. 自動的に目次ページへ移動するので、読みたい話を選ぶ

## 制限事項

- 1つのブラウザには作品を1つだけ保存します（新しいzipをアップロードすると上書きされます）
- ブラウザの閲覧データ（サイトデータ）を消去すると、保存した内容も消えます
- zip内の話数ファイルは `001.html` / `001.txt` のような3〜4桁の連番ファイル名を想定しています
  （notebookが出力する形式そのままであれば問題ありません）
